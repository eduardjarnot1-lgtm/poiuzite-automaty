# Použité automaty

Website for Použité automaty, a Czech business selling used, refurbished and renovated vending machines, with a focus on instant coffee and hot-drink machines.

It is a static site generated by a small Node script with no dependencies. Product data lives in JSON files, separate from the templates, so the catalogue can be updated without touching HTML.

## Build and preview

```sh
node scripts/build.mjs     # writes the site to dist/
node scripts/check.mjs     # checks links, anchors, titles, descriptions, headings, alt text
npx http-server dist -p 8080
```

Netlify builds it with `netlify.toml` (command `node scripts/build.mjs`, publish `dist`).

## Pages

| URL | Page |
| --- | --- |
| `/` | Homepage: hero, introduction, categories, latest machines, services, call to action |
| `/automaty/` | All categories |

| `/automaty/<category>/<product>/` | Product detail with gallery, specs table, enquiry form, related machines |
| `/repasovane-automaty/` | Refurbished and renovated machines, condition grades, the scroll-controlled video |
| `/nahradni-dily/` | Spare parts enquiry |
| `/servis/` | Repairs, servicing and maintenance |
| `/o-nas/` | About the company |
| `/kontakt/` | Phone, e-mail, address and contact form |
| `/dekujeme/` | Thank-you page after a form is sent without JavaScript |

Templates are in `scripts/lib/`: `components.mjs` (layout, header, footer, product card, enquiry form) and `pages.mjs` (one function per page).

## Editing content

- `data/site.json`: company name, contact details, `baseUrl` (needed for canonical links and the sitemap; Netlify's own URL is used if empty), form endpoint, price settings and the wording of the condition grades.
- `data/categories.json`: categories, their intros and meta descriptions.
- `data/products.json`: the machines. Each has `id`, `slug`, `category`, `name`, `manufacturer`, `model`, `type`, `condition` (`pouzity`, `repasovany` or `renovovany`), `conditionDetails`, `summary`, `description` (paragraphs), `specs` (`label`, `value`, `key: true` to show it on the card), `features`, `paymentSystems`, `warranty`, `price` (number, or `null` for "Cena na dotaz"), `availability`, `images` (`src`, `alt`, optional `width`, `height`, `thumb`, `srcset: [{src, w}]`), `dateAdded` and optional `related` ids.
- Product photos go in `assets/products/<slug>/` and are referenced as `assets/products/<slug>/1.webp`.

The build stops with a clear message if a product has a missing field, an unknown category or condition, a duplicate slug, or an image without alt text.

**Placeholders.** No real product data, photos, prices or contact details were supplied yet, so the catalogue holds six sample items (`"placeholder": true`) and missing facts are shown as dashed yellow "doplníme / doplní se" labels. Sample products are marked "Vzorová položka", carry a notice on the catalogue and are `noindex`. Replace them with real machines, fill in `site.json`, and set each condition's `verified` to `true` once the wording is confirmed.

**Catalogue controls follow the data.** A filter appears only when at least two machines differ in that field (manufacturer, condition, type), price filtering and sorting appear once two machines have prices, and search appears from `catalogue.searchMinProducts` machines (8). Without JavaScript the full list still shows.

## Forms

All forms are one Netlify form named `poptavka` with fields `jmeno`, `firma`, `email`, `telefon`, `zprava`, plus hidden `typ` (which page or service) and `automat` (the product, on product pages). Netlify detects it at deploy; turn on notifications in the Netlify dashboard under Forms. To use another service (Formspree, Basin, your own handler), set `forms.endpoint` in `site.json`.

With JavaScript, the form validates with Czech messages and sends without leaving the page, then shows a thank-you message or an error with the phone and e-mail. Without JavaScript it posts normally and lands on `/dekujeme/`. A hidden honeypot field filters simple spam bots.

## Homepage hero

The hero is a workshop scene split into two depth layers, with the Czech copy, navigation, button and before/after switch as plain HTML on top:

- `assets/img/hero-bg.webp`: the workshop (wall, workbench, floor) with the machines and platform removed, softly blurred towards the edges.
- `assets/img/hero-fg-before.webp` and `hero-fg-after.webp`: the three machines on the concrete platform, opened up for repair and finished.

The pointer moves the far layer less than the near one, and tilts the machines very slightly. The platform gets extra volume from CSS shading, and the glass fronts carry a faint reflection that follows the pointer. Phones, touch screens and `prefers-reduced-motion` get a still scene. "Před opravou" and "Po opravě" wipe between the two machine layers.

The layers are built from the two flattened mockups in `assets/source/` by `tools/build_layers.py`. It removes the text baked into the mockups, cuts out the machines and platform, and fills in the workshop behind them. To rebuild:

```sh
pip install opencv-python-headless numpy pillow
python3 tools/build_layers.py
```

## Refurbishment page video

The "Druhá šance začíná důkladnou péčí" section (on `/repasovane-automaty/`, rendered by `refurbished()` in `scripts/lib/pages.mjs`) is driven by scrolling. The section is tall and its frame stays pinned to the screen while one scroll timeline runs in two phases:

1. **Service cover.** A cover panel over the section lifts from its top edge and folds once across the middle, like a vending machine's service hatch, revealing the video still on its first frame. It is a separate layer made with CSS 3D transforms. The video underneath never moves or changes size.
2. **Video.** Scrolling moves the video from its first frame to its last, forwards or backwards, with the step copy in sync.

When the video ends, the page carries on to the footer.

- **Copy:** plain HTML in `scripts/lib/pages.mjs`. Each `.scrub-panel` has `data-from` / `data-to`, the seconds of video during which it shows. Comments there say what the footage shows at each point.
- **Scroll length:** on `.scrub` in `assets/css/servis.css`, in viewport heights. `--cover-distance` is the cover fold (100, or 80 on phones) and `--scrub-distance` the video (400). Higher means slower.
- **Fold shape:** angles, lift and shading are in `renderCover()` in `assets/js/scrub.js`.

The cover took inspiration from React Bits' PaperCrumple but doesn't use it: that component is a React and Three.js sheet crumpled by pointer drag, and a two-leaf CSS fold is lighter and maps directly onto scroll.
- **Smoothing:** `EASE` at the top of `assets/js/scrub.js`.

The footage is an exploded-assembly animation, so the section labels it "Ilustrační animace" and the copy describes the process, not what the footage literally shows.

Video files in `assets/video/`:

- `servis-scrub-1280.mp4` / `.webm`: desktop
- `servis-scrub-720.mp4` / `.webm`: phones (up to 760 px wide)
- `servis-scrub-start.jpg`: the first frame, shown until the video is ready
- `servis-scrub-poster.jpg`: the still used when the video can't run

The original video is kept in `assets/source/servis-automatu-original.mp4`. The scrub files are encoded with a keyframe every 6 frames so seeking stays quick in both directions:

```sh
SRC=assets/source/servis-automatu-original.mp4
ffmpeg -i $SRC -an -c:v libx264 -crf 28 -preset slow -g 6 -keyint_min 6 -sc_threshold 0 -bf 0 -pix_fmt yuv420p -movflags +faststart assets/video/servis-scrub-1280.mp4
ffmpeg -i $SRC -an -vf scale=720:-2 -c:v libx264 -crf 27 -preset slow -g 6 -keyint_min 6 -sc_threshold 0 -bf 0 -pix_fmt yuv420p -movflags +faststart assets/video/servis-scrub-720.mp4
ffmpeg -i $SRC -an -c:v libvpx-vp9 -crf 39 -b:v 0 -g 6 assets/video/servis-scrub-1280.webm
ffmpeg -i $SRC -an -vf scale=720:-2 -c:v libvpx-vp9 -crf 37 -b:v 0 -g 6 assets/video/servis-scrub-720.webm
```

If the video length changes, update `data-duration` on the section and the panel timings.

Visitors who prefer reduced motion, browsers that can't play the video, and any failed load get a normal section instead, with no cover: the poster, then all the copy and steps laid out in order. The script waits for the page to load before fetching video, and plays it from memory if the server doesn't support range requests (which seeking needs).
